# Инструкции для Claude

## Git: изменения всегда попадают в main (решение владельца 14.11.2026)

- В начале работы взять свежий `main` (в облаке — свежий клон; локально — `git pull`).
- В конце каждой задачи с изменениями: commit → push → pull request → **смержить PR в `main` самостоятельно, без отдельного разрешения** → удалить рабочую ветку. Работа не считается законченной, пока изменения не в `main`.
- Не мержить, если: проверки по задаче не прошли; есть конфликт с `main`, который нельзя решить без догадок; те же файлы сейчас ведёт другой исполнитель. В этих случаях оставить PR открытым и коротко написать владельцу причину.
- В конце ответа сообщить: что изменилось, номер/ссылку PR и что он смержен в `main`.
- Мерж в `main` — это сохранение кода, а не публикация, установка или деплой: они — только по прежним правилам проекта.
